# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`sbb-tui` is a Bubbletea-based terminal UI that talks to the public Swiss transport API at `transport.opendata.ch/v1` to look up timetables. Single binary, Go 1.25, no database, no tests in the repo.

## Toolchain

The repo is `mise`-managed. After cloning, run `mise install` then `mise run init` to install the pre-commit hooks. The `[[hooks.enter]]` blocks in `mise.toml` warn on entry if either step is missing.

Pre-commit (configured in `.pre-commit-config.yaml`) runs `gofumpt`, `goimports`, and `golangci-lint` on every commit, and `conventional-pre-commit` on the commit message. Run the whole suite manually with `pre-commit run --all-files`, or one hook via `mise run pre-commit-run <hook-id> --all-files` (the task autocompletes hook ids from the YAML).

Markdown linting is deliberately *not* a pre-commit hook — it warns instead of blocking. Run it explicitly with `mise run lint:markdown` (add `--fix` to auto-fix). `CHANGELOG.md` is excluded.

`mise run docs` serves godoc at http://localhost:6060 for browsing the source.

## Build / run

- Build: `go build` produces `./sbb-tui`. The release pipeline injects the version via `-ldflags "-X main.version=<tag>"`; local builds report `version = "dev"` and skip the "newer version available" check (see `util/version.go`).
- Run: `./sbb-tui` (or with `--from`, `--to`, `--date DD.MM.YYYY`, `--time HH:MM`, `--arrival`, `--animations=false`, `--nerdfont=false`).
- Lint: `golangci-lint run`. Only `revive` is enabled with the `exported` rule, so **every exported identifier needs a doc comment** — adding an unexported type is fine, but `Foo` without a `// Foo ...` line will fail lint.

## Releases — do not hand-edit

Releases are fully automatic. Pushing to `master` triggers `.github/workflows/release.yml`, which:

1. Runs `semantic-release` (config in `.releaserc.json`). It reads Conventional Commits to decide the next version, generates release notes, updates `CHANGELOG.md`, and creates a git tag + GitHub release.
2. On a new tag, runs GoReleaser (`.goreleaser.yaml`) to build cross-platform binaries and push the Homebrew formula to `Necrom4/homebrew-tap`.

Implications when working in the repo:

- **Never hand-edit `CHANGELOG.md`** — it's regenerated by semantic-release and edits will be clobbered.
- Commit message *type* determines the version bump: `feat:` → minor, `fix:` → patch, anything else → no release. Pick deliberately.
- The README has an intentional caveat that `v1.X.X` is treated as experimental, so breaking changes can ship under `feat:` / `fix:` without a major bump; document them in the commit body.

## Architecture

`main.go` → `config.LoadConfig()` → `ui.NewModel(cfg)` → `tea.NewProgram(...).Run()`. CLI flags layer on top of the YAML config (`$HOME/.config/sbb-tui/config.yaml`, with the OS default config dir as fallback — see `config.configFilePath`). Inside `LoadConfig`, the theme is built by `mergeTheme(DefaultTheme(), fileTheme)` which only copies *non-empty* fields, so partial themes work; there's an explicit `// NOTE:` reminder to update `mergeTheme` whenever `Theme` gains a field.

Package layout:

- `model/` — JSON shapes for the transport API (`Connection`, `Section`, `Timestamp`). `SwissLocation` is `Europe/Zurich` with a fixed-offset fallback, and `main.go` blank-imports `time/tzdata` so the zoneinfo lookup never fails on minimal containers.
- `api/` — Thin `http.Get` wrappers around `/v1/locations` (autocomplete) and `/v1/connections` (search). No client struct or shared state.
- `util/` — `NewerVersion(current)` hits the GitHub releases API to power the footer's update badge. Returns empty when `current == "dev"`.
- `ui/` — All of the Bubbletea Model/View/Update lives here.

### UI internals worth knowing before touching `ui/`

- `appModel.headerOrder` is the canonical tab order, mixing `kindInput` (the 4 `textinput.Model`s in `inputs`) and `kindButton` (`swap`, `isArrivalTime`, `search`). Most navigation logic in `update.go` keys off this list, not the input array.
- **Date and time inputs do their own keystroke handling** in `updateInputs` — they strip delimiters, validate digit-by-digit (`validateDateDigits` / `validateTimeDigits` reject impossible partial inputs like a date starting with `4`), then re-insert `.` / `:` at fixed positions. This is why arbitrary cursor movement still keeps `DD.MM.YYYY` shape intact.
- Station suggestions are debounced 300ms (`suggestDebounce`) and gated by a per-input sequence number (`suggestSeq`) — only the latest tick fires the fetch, so abandoned keystrokes don't race. The fetched names are then run through `adaptSuggestions` / `prefixMatchLen`, which graft the user's literal typed prefix onto the suggestion and skip diacritics/punctuation (so `"zur"` matches `"Zürich HB"`). The textinput widget itself only does `HasPrefix`, so without this graft suggestions would never show.
- `right` is overloaded: it accepts the autocomplete suggestion *only* when the cursor is at end-of-string; mid-string it temporarily clears `KeyMap.AcceptSuggestion` and just moves the cursor. Don't "simplify" this.
- `q` quits only when a button has focus — text inputs need to accept the literal `q` character.
- `ui/animation.go` is a small named-animation registry running off a single 30 FPS ticker (`animationTickMsg`). Individual animations (`logo_build.go`, `shine.go`, `tagline_build.go`, `loading.go`) register by name and read progress via `animator.Progress(name)`. Adding a new animation = add a constant name, `Start(name, duration)` it, branch on it in the relevant render path.
- The start-screen "shine" effect in `ui/shine.go` (346 lines — the largest file in the repo) is a real multi-stage pipeline, not a cosmetic loop: a moving band sweeps the logo/tagline (`applyShine` → `shineFactor` → `newShinePalette` → `renderGrid`), and `shineTarget` picks polarity from WCAG relative luminance so bright bases darken and dark bases brighten under the band. Two named animations drive it (`logoShine`, `textShine`), chained into the start-screen sequence via `shineRestartMsg`. Touching anything in `ui/shine.go` will likely ripple into `ui/logo_build.go`, `ui/tagline_build.go`, and `appModel.renderStartScreen` in `view.go`.
- `ui/sbb-logo.txt` and `ui/sbb-logo-nerdfont.txt` are `//go:embed`-ed into `view.go`. Two icon sets (Nerd Font / Unicode fallback) live in `ui/icons.go`, selected once at startup from `cfg.NerdFont`.
- Hard minimum terminal size is 80×24 (`minTermWidth` / `minTermHeight` in `styles.go`); below that the view degrades to a single warning message.

## Contributing flow (from CONTRIBUTING.md)

Open an issue first, fork, then PR. Commits must be Conventional Commits (enforced by the commit-msg hook) and granular — one logical change per commit, meaningful titles, body when the diff isn't self-explanatory. Godoc-style comments on exported identifiers (also enforced by `revive`).
